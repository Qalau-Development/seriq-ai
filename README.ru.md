# SerIQ AI

**ИИ-помощник для домашней реабилитации**

[English](README.md) | Русский

SerIQ анализирует упражнение на разгибание локтя по видео с веб-камеры или по загруженной записи. Pose-estimation отслеживает руку, а собственный ML-классификатор определяет, был ли каждый цикл упражнения выполнен полностью. Пользователь видит нейтральный результат: «Выполнено» или «Проверьте инструкцию».

> **Статус:** работающий прототип. Сайт, API и обученная модель работают на [seriq-ai.qalau.com](https://seriq-ai.qalau.com) (`"mode":"model"`): загрузка или запись с веб-камеры, анализ собственным классификатором, график угла локтя, сводка занятия и история, казахский и русский. Flutter-приложение для Android и iOS работает с тем же API. Метрики модели и их ограничения: [docs/model-evaluation.md](docs/model-evaluation.md). См. [Текущий статус](#текущий-статус).

## Постановка задачи

Пациенты после инсульта часто выполняют реабилитационные упражнения дома, без специалиста рядом. Им трудно понять, выполнено ли упражнение полностью.

Кейс требует прототип, который оценивает одно упражнение, **разгибание локтя (E02)**, по видео с камеры или из загруженной записи. Требования ТЗ:

1. Сценарий тренировки: видеоинструкция и захват движения через камеру или загрузку видео.
2. Определение ключевых точек руки с помощью pose-estimation модели и отслеживание цикла разгибания локтя.
3. Собственная ИИ-модель на последовательностях координат или углов руки, которая классифицирует цикл как `complete` или `incomplete`, с оценкой уверенности и сравнением с базовым классификатором. При низкой уверенности приложение предлагает пересмотреть инструкцию и не даёт корректирующих медицинских указаний. Данные делятся на train, validation и test строго по ID добровольца. Качество указывается через balanced accuracy, F1 и матрицу ошибок.
4. Локальная сводка занятия: число распознанных циклов, их классы и наглядное отображение.

## Предлагаемое решение

1. Найти ключевые точки кисти на каждом кадре с помощью MediaPipe Hand Landmarker. В датасете плечо обычно вне кадра, поэтому локоть находится как центр окружности, по которой движется запястье (радиус привязан к размеру кисти).
2. Превратить их во временной ряд угла локтя, не зависящий от разрешения, ориентации камеры и частоты кадров.
3. Разбить запись на отдельные циклы упражнения.
4. Классифицировать каждый цикл собственной моделью, обученной на датасете кейса, и сравнить её с простым базовым классификатором.
5. Показать пользователю нейтральный результат и сводку занятия.

## Планируемые возможности

Ничего из этого пока не реализовано.

- Видеоинструкция к упражнению на разгибание локтя
- Загрузка видео и запись с веб-камеры
- Pose-estimation руки
- Выделение циклов и классификация каждого (`complete` / `incomplete`) с уверенностью
- Нейтральные сообщения, при низкой уверенности — предложение пересмотреть инструкцию
- Сводка занятия: всего циклов, число выполненных и невыполненных, результат по каждому циклу, график
- Интерфейс на казахском и русском или английском, рассчитанный на пожилых пользователей и пациентов

## Схема работы

```text
Инструкция -> Запись или загрузка -> Pose-estimation -> Ряд углов локтя
           -> Выделение циклов -> Классификация -> Результат и сводка занятия
```

## Обзор архитектуры

Сайт и Flutter-приложение отправляют запись в один REST API. Бэкенд на FastAPI запускает общее AI-ядро (pose-estimation, угол локтя, признаки, классификатор) и возвращает результат в JSON. Видео удаляется после анализа, базы данных нет, история занятий хранится на устройстве пользователя. Подробнее: [docs/architecture.md](docs/architecture.md), контракт API: [docs/api.md](docs/api.md).

## Установка

| Часть | Папка | Что нужно |

## Локальная разработка

Каждая часть запускается в своём терминале, пути — от корня репозитория.

### Бэкенд (режим мока)

```bash
cd backend
source .venv/bin/activate
uvicorn app.main:app --reload --port 8000    # http://localhost:8000/api/v1/health
pytest -q
```

Настройки читаются из переменных окружения `SERIQ_MODE` (`mock` или `model`), `SERIQ_MAX_UPLOAD_MB` и `SERIQ_MODEL_PATH`, см. [.env.example](.env.example).

### Сайт

```bash
cd apps/web
npm run dev        # http://localhost:3000
npm run lint
npm run build
```

Сайт обращается к относительному адресу `/api/v1/...`. При разработке Next.js пересылает `/api` на `SERIQ_API_PROXY` (по умолчанию `http://localhost:8000` — локальный бэкенд из раздела выше). Чтобы работать с боевым API без локального бэкенда:

```bash
SERIQ_API_PROXY=https://seriq-ai.qalau.com npm run dev
```

### Мобильное приложение

Телефон на Android с отладкой по USB или эмулятор:

```bash
cd apps/mobile
flutter run --dart-define=API_BASE_URL=https://seriq-ai.qalau.com/api/v1
flutter analyze
flutter test
flutter build apk --release --dart-define=API_BASE_URL=https://seriq-ai.qalau.com/api/v1
# APK: apps/mobile/build/app/outputs/flutter-apk/app-release.apk
```

APK также собирает GitHub Actions: Actions → **Mobile** → запуск → Artifacts → `seriq-android-apk`.

`localhost` на телефоне — это сам телефон. Чтобы телефон, подключённый по USB, ходил в локальный бэкенд (отладочная сборка): `adb reverse tcp:8000 tcp:8000` и `flutter run --dart-define=API_BASE_URL=http://localhost:8000/api/v1`.

iOS: на macOS с Xcode запустите `flutter run` в `apps/mobile` на симуляторе или iPhone (подпись — Apple ID в Xcode). GitHub Actions проверяет, что iOS-сборка компилируется (`flutter build ios --no-codesign`).

Подробнее: [apps/mobile/README.md](apps/mobile/README.md).

### Деплой

Деплой автоматический, вручную никто не выкладывает:

1. На каждый push в любую ветку GitHub Actions запускает проверки ([.github/workflows/ci-cd.yml](.github/workflows/ci-cd.yml)): конфигурация сервера, тесты бэкенда и AI-движка, линтер и сборка сайта, `flutter analyze` и `flutter test`, сборка всех сервисов с проверкой, что сайт и API отвечают. Изменения в `apps/mobile/` дополнительно собирают APK и iOS-приложение ([.github/workflows/mobile.yml](.github/workflows/mobile.yml)).
2. После слияния в `main` и зелёных проверок GitHub Actions подключается к серверу по SSH и запускает [infrastructure/scripts/deploy.sh](infrastructure/scripts/deploy.sh) для этого коммита.
3. Скрипт собирает сервисы, для которых есть код (`caddy`, `backend`, `web` в [docker-compose.yml](docker-compose.yml)), ждёт их healthcheck'и и проверяет главную страницу и `/api/v1/health` по HTTPS. Если что-то не так — откатывается на предыдущий коммит.

На сервере HTTPS принимает Traefik (Dokploy) и передаёт запросы в Caddy, который отправляет `/api/*` в бэкенд, а остальное — на сайт. Доступ к серверу, ключи и `.env` сервера в репозитории не хранятся. Подробнее: [docs/architecture.md](docs/architecture.md#deployment).

## Работа с данными и приватность

- Датасет кейса **не** хранится в этом репозитории. Видео, архивы и обработанные данные исключены через `.gitignore`.
- Источник: *An upper limb stroke rehabilitation exercise video dataset*, Mendeley Data, DOI [10.17632/49h9dcwx5v.1](https://data.mendeley.com/datasets/49h9dcwx5v/1), CC BY 4.0.
- Планируемому приложению не нужны персональные данные. Загруженные видео должны обрабатываться и не сохраняться, а сводка занятия — оставаться на устройстве пользователя.
- SerIQ — демонстрационный инструмент, **а не медицинское изделие**. Он не ставит диагнозов, не назначает лечение и не даёт корректирующих медицинских указаний.

## Методика оценки модели

Кратко из [docs/model-evaluation.md](docs/model-evaluation.md):

- Разбиение по ID добровольца: добровольцы 01–05 для обучения с кросс-валидацией leave-one-subject-out, доброволец 08 — отложенная тестовая выборка.
- Метрики: balanced accuracy, precision, recall, F1, матрица ошибок, сравнение с базовым классификатором.
- Порог уверенности подбирается на фолдах кросс-валидации, а не на тесте.
