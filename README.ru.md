# SerIQ AI

**ИИ-помощник для домашней реабилитации**

[English](README.md) | Русский

SerIQ помогает людям после инсульта проверять домашнее реабилитационное упражнение. Человек снимает одно повторение (или загружает видео), pose-estimation отслеживает кисть, а собственный ML-классификатор решает, было ли повторение выполнено полностью. Пользователь видит нейтральный результат, измеренное значение, график и сводку занятия. Обученные модели есть для разгибания локтя (E02), подъёма запястья (E03) и раскрытия кисти (E04). В API есть каталог четырёх упражнений датасета (E01–E04) с признаком, какие из них готовы.

> **Статус:** работающий прототип. Сайт, API и обученная модель работают на [seriq-ai.qalau.com](https://seriq-ai.qalau.com) (`"mode":"model"`): библиотека упражнений, загрузка или запись с веб-камеры, анализ собственными классификаторами, график измеряемого значения, сводка занятия и история, казахский и русский. Flutter-приложение для Android и iOS работает с тем же API. Метрики модели и их ограничения: [docs/model-evaluation.md](docs/model-evaluation.md). См. [Текущий статус](#текущий-статус).

## Запуск одной командой

Нужны Node.js 22 и Python 3.12 (или [uv](https://docs.astral.sh/uv/)), macOS или Linux (Windows — через WSL).

```bash
git clone https://github.com/Qalau-Development/seriq-ai.git
cd seriq-ai
./start.sh
```

Скрипт проверит Node.js, Python и порты 3000 и 8000, поставит библиотеки бэкенда и сайта, скачает модель MediaPipe с проверкой контрольной суммы, запустит бэкенд с настоящей моделью и сайт и откроет `http://localhost:3000`. Первый запуск занимает несколько минут. Остановить — Ctrl+C. Заняты порты: `BACKEND_PORT=8001 WEB_PORT=3001 ./start.sh`.

## Происхождение

SerIQ начался как кейс AI-Sana Shakarim Solveathon: AI & Medicine-2026 (Университет имени Шакарима, Семей, Казахстан). Кейс и датасет взяты оттуда; проект продолжается как продукт для домашней реабилитации.

- [Сайт конкурса](https://solveathon.shakarim.edu.kz/)
- [Кейсы](https://solveathon.shakarim.edu.kz/en/problems/): ТЗ кейса и датасет

## Постановка задачи

Пациенты после инсульта часто выполняют реабилитационные упражнения дома, без специалиста рядом. Им трудно понять, выполнено ли упражнение полностью. SerIQ нейтрально проверяет каждое повторение по видео и хранит историю занятий на устройстве пользователя. Медицинских советов он не даёт.

В датасете четыре упражнения. API описывает все четыре; обученные модели есть для E02, E03 и E04, а `GET /api/v1/exercises` показывает, какие упражнения готовы.

| Код | Упражнение | Измеряемое значение (`measure`) |
|---|---|---|
| `E01` | Подъём предмета | `lift_height`, в длинах кисти |
| `E02` | Разгибание локтя | `elbow_angle`, градусы |
| `E03` | Подъём запястья | `wrist_lift`, градусы |
| `E04` | Раскрытие кисти | `hand_openness`, проценты от начального |

## Как это работает

1. Найти ключевые точки кисти на каждом кадре с помощью MediaPipe Hand Landmarker. В датасете плечо обычно вне кадра, поэтому для E02 локоть находится как центр окружности, по которой движется запястье (радиус привязан к размеру кисти).
2. Превратить точки во временной ряд, не зависящий от разрешения, ориентации камеры и частоты кадров (E02 — угол локтя, E03 — поворот кисти, E04 — раскрытие кисти).
3. Посчитать признаки ряда и классифицировать повторение собственной моделью, обученной на датасете. Модель сравнивается с простыми базовыми. При низкой уверенности ответ `uncertain`.
4. Показать пользователю нейтральный результат и добавить его в сводку занятия.

Одна запись — одно повторение.

## Возможности

- Загрузка видео и запись с веб-камеры (сайт), запись и загрузка в мобильном приложении
- Pose-estimation кисти; линия руки поверх собственного видео пользователя на экране результата
- Классификация повторения (`complete` / `incomplete` / `uncertain`) с уверенностью
- Нейтральные сообщения; при низкой уверенности — предложение проверить инструкцию, без корректирующих медицинских указаний
- Сайт: библиотека упражнений и инструкция к каждому упражнению (шаги и советы по съёмке текстом)
- Сайт: сводка занятия и история на устройстве с фильтром по упражнению; график измеряемого значения каждого упражнения
- Интерфейс на казахском и русском, рассчитанный на пожилых пользователей
- Каталог упражнений в API для E01–E04 и мок-ответы по всем четырём

## Схема работы

```text
Инструкция -> Запись или загрузка -> Точки кисти -> Сигнал упражнения
           -> Признаки -> Классификация -> Результат и сводка занятия
```

## Обзор архитектуры

Сайт и Flutter-приложение отправляют запись в один REST API. Бэкенд на FastAPI запускает общее AI-ядро (pose-estimation, угол локтя, признаки, классификатор) и возвращает результат в JSON. Видео удаляется после анализа, базы данных нет, история занятий хранится на устройстве пользователя. Подробнее: [docs/architecture.md](docs/architecture.md), контракт API: [docs/api.md](docs/api.md). Бэкенд также отдаёт каталог упражнений (`GET /api/v1/exercises`) и возвращает измеряемое значение упражнения в поле `measure`.

## Локальная разработка

Каждая часть запускается в своём терминале, пути — от корня репозитория.

### Бэкенд (режим мока)

```bash
cd backend
source .venv/bin/activate
uvicorn app.main:app --reload --port 8000    # http://localhost:8000/api/v1/health
pytest -q
```

Настройки читаются из переменных окружения `SERIQ_MODE` (`mock` или `model`), `SERIQ_MAX_UPLOAD_MB` и `SERIQ_MODEL_PATH`, см. [.env.example](.env.example).

### Сайт

```bash
cd apps/web
npm run dev        # http://localhost:3000
npm run lint
npm run build
```

Сайт обращается к относительному адресу `/api/v1/...`. При разработке Next.js пересылает `/api` на `SERIQ_API_PROXY` (по умолчанию `http://localhost:8000` — локальный бэкенд из раздела выше). Чтобы работать с боевым API без локального бэкенда:

```bash
SERIQ_API_PROXY=https://seriq-ai.qalau.com npm run dev
```

### Мобильное приложение

Телефон на Android с отладкой по USB или эмулятор:

```bash
cd apps/mobile
flutter run --dart-define=API_BASE_URL=https://seriq-ai.qalau.com/api/v1
flutter analyze
flutter test
flutter build apk --release --dart-define=API_BASE_URL=https://seriq-ai.qalau.com/api/v1
# APK: apps/mobile/build/app/outputs/flutter-apk/app-release.apk
```

APK также собирает GitHub Actions: Actions → **Mobile** → запуск → Artifacts → `seriq-android-apk`.

`localhost` на телефоне — это сам телефон. Чтобы телефон, подключённый по USB, ходил в локальный бэкенд (отладочная сборка): `adb reverse tcp:8000 tcp:8000` и `flutter run --dart-define=API_BASE_URL=http://localhost:8000/api/v1`.

iOS: на macOS с Xcode запустите `flutter run` в `apps/mobile` на симуляторе или iPhone (подпись — Apple ID в Xcode). GitHub Actions проверяет, что iOS-сборка компилируется (`flutter build ios --no-codesign`).

Подробнее: [apps/mobile/README.md](apps/mobile/README.md).

### Деплой

Деплой автоматический, вручную никто не выкладывает:

1. На каждый push в любую ветку GitHub Actions запускает проверки ([.github/workflows/ci-cd.yml](.github/workflows/ci-cd.yml)): конфигурация сервера, тесты бэкенда и AI-движка, линтер и сборка сайта, `flutter analyze` и `flutter test`, сборка всех сервисов с проверкой, что сайт и API отвечают. Изменения в `apps/mobile/` дополнительно собирают APK и iOS-приложение ([.github/workflows/mobile.yml](.github/workflows/mobile.yml)).
2. После слияния в `main` и зелёных проверок GitHub Actions подключается к серверу по SSH и запускает [infrastructure/scripts/deploy.sh](infrastructure/scripts/deploy.sh) для этого коммита.
3. Скрипт собирает сервисы, для которых есть код (`caddy`, `backend`, `web` в [docker-compose.yml](docker-compose.yml)), ждёт их healthcheck'и и проверяет главную страницу и `/api/v1/health` по HTTPS. Если что-то не так — откатывается на предыдущий коммит.

На сервере HTTPS принимает Traefik (Dokploy) и передаёт запросы в Caddy, который отправляет `/api/*` в бэкенд, а остальное — на сайт. Доступ к серверу, ключи и `.env` сервера в репозитории не хранятся. Подробнее: [docs/architecture.md](docs/architecture.md#deployment).

## Работа с данными и приватность

- Датасет **не** хранится в этом репозитории. Видео, архивы и обработанные данные исключены через `.gitignore`.
- Источник: *An upper limb stroke rehabilitation exercise video dataset*, Mendeley Data, DOI [10.17632/49h9dcwx5v.1](https://data.mendeley.com/datasets/49h9dcwx5v/1), CC BY 4.0.
- Приложению не нужны персональные данные, аккаунтов нет. Загруженное видео анализируется и удаляется; история занятий остаётся на устройстве пользователя. Что проверено и как: [docs/privacy-and-security.md](docs/privacy-and-security.md).
- SerIQ — демонстрационный инструмент, **а не медицинское изделие**. Он не ставит диагнозов, не назначает лечение и не даёт корректирующих медицинских указаний.

## Оценка модели

Кратко из [docs/model-evaluation.md](docs/model-evaluation.md). Метод одинаков для всех упражнений: разбиение по ID добровольца, кросс-валидация по добровольцам, один тестовый прогон после фиксации модели и порогов. Модель E02 `e02-logreg2-1`:

- Разбиение по ID добровольца: добровольцы 01–05 для обучения с кросс-валидацией leave-one-subject-out, доброволец 08 — тест, один прогон после фиксации модели и порогов.
- Метрики: balanced accuracy, precision, recall, F1, матрица ошибок, сравнение с двумя базовыми (класс большинства и один порог).
- Кросс-валидация: balanced accuracy 1,000 (базовая «класс большинства» 0,5, базовая «один порог» 1,000).
- Тестовый доброволец 08 (20 видео): balanced accuracy 1,000. 95%-й интервал для доли верных ответов 0,83–1,00, и все тестовые видео от одного человека.
- E04 `e04-logreg2-1` (тестовый доброволец 09): balanced accuracy 1,000 на 16 из 20 видео, в которых модель уверена (охват 0,80; 4 видео `uncertain` из-за потери кисти). 95%-й интервал доли верных ответов 0,79–1,00.
- E03 `e03-logreg2-1` (тестовый доброволец 10): balanced accuracy 1,000 на 13 из 20 уверенных видео (охват 0,65; 7 видео `uncertain` из-за потери кисти). 95%-й интервал 0,75–1,00.
- Каждая тестовая выборка — один человек. Ограничения каждой модели перечислены в документе.
