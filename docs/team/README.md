## Что мы делаем, в двух словах

Пользователь снимает на камеру одно повторение упражнения «разгибание локтя» или загружает видео. Сервер находит на видео плечо, локоть и запястье, считает угол локтя по кадрам и отдаёт эти данные нашей обученной модели. Модель решает: `complete`, `incomplete` или `uncertain` (не уверена). Пользователь видит «Выполнено» или «Проверьте инструкцию», график угла и сводку занятия.

## Общие правила

1. **Датасет, видео добровольцев и `.env` никогда не попадают в GitHub.** Репозиторий публичный.
2. **Работай только в своих папках.** Нужно что-то поменять у другого — сначала спроси.
3. **Контракт API не меняем в одиночку.** Предлагаешь изменение — все трое соглашаются.
4. **Моковые ответы — не результат модели.** В ответе API поле `source` всегда показывает, откуда данные: `mock` или `model`. Никаких случайных чисел вместо результата.
5. **Никаких медицинских советов** в интерфейсе. Только «Выполнено» или «Проверьте инструкцию» и нейтральные подсказки вроде «Убедитесь, что рука видна целиком».
6. **Видео пользователя не храним.** История занятий — только на устройстве.
7. **Видео добровольца 08 — тестовые.** Для подбора модели их не используем, и в демо на защите лучше показывать именно их или свои записи, а не видео из обучения.
8. **Open Source можно и нужно использовать, но открыто.** Любая сторонняя библиотека, модель, датасет или заимствованная идея записывается в [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md) **в том же PR**, где она появилась: название, ссылка, лицензия, для чего используется. У моделей и датасетов лицензию проверяем отдельно от кода. GPL/AGPL — только после обсуждения с командой. Чужое не выдаём за своё.

## Git: как работаем

```bash
# один раз
git clone https://github.com/Qalau-Development/seriq-ai.git
cd seriq-ai

# каждый работает в своей ветке
git checkout -b web          # №1
git checkout -b mobile       # №2 (для сервера можно ветку infra)
git checkout -b ai           # №3

# сохранить работу
git add <файлы>
git commit -m "Добавлен экран результата анализа"
git push -u origin <ветка>

# забрать свежий main к себе
git fetch origin
git merge origin/main
```

- Сообщения коммитов на русском, коротко, что сделано: «Добавлен экран истории».
- В `main` сливаем через Pull Request на GitHub, **без обязательного ревью**, но часто, хотя бы раз в 2–3 часа.
- **`main` всегда рабочий**: перед слиянием проверь, что твоя часть собирается и запускается (команды — в чек-листе твоего файла).
- Коммиты логические: одна законченная правка — один коммит, чтобы его можно было откатить отдельно.
- Перед `git add` смотри `git status`: в списке не должно быть видео, `.env`, `node_modules`, `build`, `.venv`.
