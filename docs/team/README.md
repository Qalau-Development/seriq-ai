## Что мы делаем, в двух словах

Домашний помощник для реабилитации руки после инсульта. Человек снимает на камеру одно повторение упражнения или загружает видео. Сервер находит на видео кисть, считает показатель движения, и наша обученная модель решает: `complete`, `incomplete` или `uncertain` (не уверена). Пользователь видит нейтральный результат, измеренное значение, график, своё видео с точками руки, сводку занятия и историю. Упражнений четыре (E01–E04): сейчас готово E02, остальные делаем по очереди. Подробно: [plans/roadmap.md](plans/roadmap.md).

Зоны №1–№3 в таблице выше закреплены в правилах команды и не менялись. Сейчас в работе: AI-движок и модели для остальных упражнений — danshikdev и Zenki-Erzat; бэкенд, а также сайт и приложение для четырёх упражнений — Yeskendirr (правки в чужих папках согласуются с их владельцами). В `main` всё идёт через Pull Request.

## Как снимать E02 (одинаково везде)

Модель смотрит на кисть и предплечье, плечо в кадре не нужно. Эти формулировки используются на сайте, в приложении и в видеоинструкции:

| Где | Текст |
|---|---|
| Совет по съёмке, напоминание перед записью | «Камера сбоку на уровне стола. Локоть на столе, предплечье и кулак целиком в кадре, ничем не закрыты.» |
| `warning_arm_not_visible` | «Кисть не всё время была видна. Убедитесь, что кулак и предплечье в кадре на протяжении всего движения.» |
| `error_no_pose_detected` | «Рука не найдена на видео. Снимите сбоку: локоть на столе, предплечье и кулак в кадре.» |

Видеоинструкция: сбоку, локоть на столе, кулак и предплечье всё время в кадре, медленное опускание до стола.

## Сервер: что нужно знать всем

- Сайт: **`https://seriq-ai.qalau.com`**. Сервер, HTTPS и CI/CD работают, на сервере идёт анализ моделью.
- **Каждое слияние в `main` автоматически деплоится** через GitHub Actions. Если после деплоя сайт не отвечает, деплой сам откатывается на прошлую версию, а запуск в Actions становится красным.
- **После своего слияния открой вкладку Actions** и убедись, что запуск зелёный. Красный — читай лог упавшего шага и пиши в чат.
- На сервере работают и другие проекты. Перед SerIQ стоит **Traefik (Dokploy)**, он общий: его не трогаем, порты наружу (`ports:`) не открываем.
- **Доступ к серверу (SSH) только у Yeskendirr.** Нужно поменять `.env`, посмотреть логи контейнера, замерить память — пиши ему.
- IP сервера, ключи, пароли и содержимое `.env` не публикуем: ни в репозитории, ни в чатах с ИИ.
- Кто что делает с сервером: Yeskendirr — доступ, `.env`, логи; Zenki-Erzat — `docker-compose.yml`, Dockerfile'ы, Caddyfile, CI/CD (часть A [его инструкции](dev2-mobile-devops.md)); danshikdev и Yeskendirr — следят, чтобы их код собирался, иначе деплой откатится.

## Общие правила

1. **Датасет, видео добровольцев и `.env` никогда не попадают в GitHub.** Репозиторий публичный.
2. **Работай только в своих папках.** Нужно что-то поменять у другого — сначала спроси.
3. **Контракт API не меняем в одиночку.** Предлагаешь изменение — все трое соглашаются.
4. **Моковые ответы — не результат модели.** В ответе API поле `source` всегда показывает, откуда данные: `mock` или `model`. Никаких случайных чисел вместо результата.
5. **Никаких медицинских советов** в интерфейсе. Только «Выполнено» или «Проверьте инструкцию» и нейтральные подсказки вроде «Убедитесь, что рука видна целиком».
6. **Видео пользователя не храним.** История занятий — только на устройстве.
7. **Тестовые добровольцы** (E01 — 07, E02 — 08, E03 — 10, E04 — 09) для подбора модели не используем: только один финальный прогон после фиксации модели и порогов. Для демо лучше показывать их записи или свои, а не видео из обучения.
8. **Open Source можно и нужно использовать, но открыто.** Любая сторонняя библиотека, модель, датасет или заимствованная идея записывается в [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md) **в том же PR**, где она появилась: название, ссылка, лицензия, для чего используется. У моделей и датасетов лицензию проверяем отдельно от кода. GPL/AGPL — только после обсуждения с командой. Чужое не выдаём за своё.

## Git: как работаем

```bash
# один раз
git clone https://github.com/Qalau-Development/seriq-ai.git
cd seriq-ai
git config user.name "<твой GitHub-ник>"
git config user.email "<твоя no-reply почта GitHub>"   # Settings → Emails на GitHub

# каждый работает в своей ветке
git checkout -b web          # №1
git checkout -b mobile       # №2 (для сервера можно ветку infra)
git checkout -b ai           # №3

# сохранить работу
git add <файлы>
git commit -m "Добавлен экран результата анализа"
git push -u origin <ветка>

# забрать свежий main к себе
git fetch origin
git merge origin/main
```

- Сообщения коммитов на русском, коротко, что сделано: «Добавлен экран истории».
- В `main` сливаем через Pull Request на GitHub, **без обязательного ревью**, но часто, хотя бы раз в 2–3 часа.
- **`main` всегда рабочий**: перед слиянием проверь, что твоя часть собирается и запускается (команды — в чек-листе твоего файла).
- Коммиты логические: одна законченная правка — один коммит, чтобы его можно было откатить отдельно.
- Перед `git add` смотри `git status`: в списке не должно быть видео, `.env`, `node_modules`, `build`, `.venv`.
