# Дорожная карта SerIQ

Статус: **рабочий файл.** В конце проекта удаляется вместе с остальным содержимым `docs/team/plans/`. Публичные документы (README, `api.md`, `architecture.md`, `model-evaluation.md`, `privacy-and-security.md`) описывают только то, что уже сделано и проверено.

## Цель

Полноценный домашний помощник для реабилитации руки после инсульта на все четыре упражнения датасета. Человек снимает одно повторение на камеру или загружает видео, сервер находит кисть, считает показатель движения, своя модель решает `complete` / `incomplete` / `uncertain`. Пользователь видит нейтральный результат, измеренное значение, график, своё видео с точками руки, сводку занятия и историю.

Рамки, которые не меняются:

- нет диагнозов и корректирующих медицинских указаний;
- видео не хранится на сервере, удаляется сразу после анализа;
- контракт API меняется только добавлением необязательных полей;
- модель E02 и её тестовые результаты не трогаем;
- не делаем: кабинет врача, игровая механика (задания, достижения, баллы, уровни, игровой мир), восстановление пароля, микросервисы, хранение видео.

## Упражнения

| Код | Что делает человек | `measure` | Train / тест-доброволец | Состояние |
|---|---|---|---|---|
| E02 | разгибание локтя до стола | `elbow_angle`, deg | 01–05 / 08 | готов, на сервере, модель `e02-logreg2-1` |
| E04 | раскрывает кулак в ладонь | `hand_openness`, percent | 01–06 / 09 | сделана разведка сигнала по train |
| E03 | поднимает кисть, предплечье на подставке | `wrist_lift`, deg | 02–06 / 10 | сделана разведка сигнала по train |
| E01 | поднимает бутылку со стола | `lift_height`, hand_lengths | 01–05 / 07 | сделана разведка сигнала по train (риск: бутылка закрывает пальцы) |

Порядок работы над моделями: E04 → E03 → E01. Тестовый доброволец каждого упражнения: один прогон после фиксации модели и порогов.

Что дала разведка (PR с `ml-training/recon.py`, графики в `docs/figures/`):

- кисть найдена в 99,4–100% кадров у каждого из 304 train-видео трёх упражнений;
- в E04 и E03 у `complete` сигнал растёт и держится на плато, у `incomplete` поднимается и возвращается: классы различает форма кривой (значение в конце, максимум минус конец), одного максимума мало;
- в E01 пик `complete` 2,7–5 длин кисти, `incomplete` 1–2,5, есть выбросы;
- у добровольца 01 нет `complete`, у добровольца 03 нет `incomplete` (E04): метрики LOSO считать по объединённым предсказаниям;
- E03: значения до 100–140° — поворот вектора «запястье → середина ладони» в кадре, а не клинический угол; в тексте результата формулировка нейтральная.

## Движок

1. Реестр `seriq_engine.exercises` (`catalog()`, `analyze_video(path, exercise)`) по согласованному стыку, описанному в [integration.md](../integration.md) (раздел про четыре упражнения). E02 идёт через прежний `pipeline`, результат тот же.
2. Для каждого упражнения: признаки формы сигнала, baseline A (класс большинства), baseline B (один порог), основная простая модель с калибровкой, LOSO-CV, фиксация, один тест, раздел в `docs/model-evaluation.md`. Сигнал не работает — стоп и отчёт без подгонки.
3. Порог `uncertain` и правило «нет сигнала» как у E02.

## Бэкенд

- Этап 1 (несколько упражнений без аккаунтов): сделан. Каталог `GET /api/v1/exercises`, поле `measure`, мок по четырём упражнениям, адаптер к движку с фолбэком на старый `pipeline` для E02.
- Этап 2 (проект аккаунтов): [accounts-plan.md](accounts-plan.md). Вход только по логину и паролю, без Google и Apple.
- Этап 3: PostgreSQL отдельно от VPS с моделью, SQLAlchemy 2.0, Alembic, регистрация и вход, профиль, удаление аккаунта. База и авторизация меняют архитектуру, поэтому начинаем только после согласования команды.
- Этап 4: сохранение занятий в облако по принципу local-first, идемпотентно по `analysis_id` и локальному UUID занятия.
- Этап 5: SerIQ Companion (LLM-помощник) только с явной галочкой согласия пользователя; в запрос уходят вопрос и готовые тексты, без данных пользователя; ключ только на сервере; приватность обновляем по факту. Подробно: раздел 10 в [accounts-plan.md](accounts-plan.md).
- Отложенные задачи: аудит безопасности и приватности сервера, замер скорости на VPS, проверка офлайн-демо, готовность сервера к нескольким моделям.

## Фронтенд: сайт и приложение (одинаково)

1. Данные: типы и разбор ответа читают `measure`; `angle_series` и `pose.elbow` необязательны; запрос передаёт выбранное упражнение; запись истории получает `exercise` и `measure`; старая история E02 читается без потерь.
2. Библиотека: четыре карточки по `GET /api/v1/exercises`; `ready: false` показывается как «Скоро», запись недоступна.
3. Сценарий занятия для любого упражнения: своя инструкция (шаги, советы по съёмке), запись или загрузка, одна запись = одно повторение. Видеоинструкции: правила команды разрешают в репозитории только `instruction-e02.mp4`; для остальных упражнений пока текстовые шаги, видеофайлы в репозиторий не кладём, пока правило не расширено.
4. Результат по `measure`: заголовок по метке; строка с измеренным значением; график `measure.series`; видео с точками кисти (линия локтя только если есть `pose.elbow`); уверенность словами. Только данные из ответа, ничего не дорисовывать.
5. История и сводка с фильтром по упражнению; главная с последними занятиями.
6. После этапов 3 и 4 бэкенда: вход и регистрация (с предупреждением, что пароль восстановить нельзя), профиль, синхронизация, статус синхронизации; позже экран помощника с галочкой согласия.

Требования: ru и kk, крупно и просто (пользователи пожилые), без медицинских советов и выводов о выздоровлении, сайт и приложение с одинаковыми текстами и видом. Работаем на моке, моделей не ждём.

## Открытые решения

- Строка результата для E04: `measure.value` — процент от начального положения кисти (например 190). Предложено показывать «Раскрытие кисти выросло на 90%» (значение минус 100).

- Тексты результата для E01, E03, E04 финализировать после того, как формулы `measure` будут зафиксированы в `model-evaluation.md`.
- Казахские тексты проверяет носитель языка.
- Хранить ли ряд `measure_series` в облаке (предложено: хранить).
- Решено: вход только по логину и паролю, без email, без восстановления пароля; игровой механики нет; Companion только с согласием.
- Срок хранения резервных копий БД и что сообщаем пользователю об остатке в копиях после удаления аккаунта.
