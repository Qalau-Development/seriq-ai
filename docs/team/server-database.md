# База аккаунтов на сервере

Статус: **включена 25.11.2026** (Yeskendirr, в серверном `.env`). База SQLite лежит в томе `seriq-ai_seriq-data` (в контейнере `/data/seriq.db`), миграции Alembic применяет `deploy.sh` перед стартом нового backend. Здесь записано, что включено, как это проверено, как отключить и что учесть при правках. Значения секретов в репозиторий, чаты и этот файл не записываются.

Каталог приложения на сервере `/opt/seriq-ai`, проект Docker Compose называется `seriq-ai`. Домен берётся из `SERIQ_DOMAIN` в `.env`; ниже он обозначен `<домен>`.

## Что включено

В `/opt/seriq-ai/.env` заданы две переменные (имена как в `.env.example`):

| Переменная | Значение |
|---|---|
| `SERIQ_DATABASE_URL` | `sqlite:////data/seriq.db` (четыре слэша: путь внутри контейнера) |
| `SERIQ_AUTH_SECRET` | случайная строка не короче 32 символов, создана на сервере; не хранится нигде, кроме `.env` (права `600`) |

Сервер не запустится с `SERIQ_DATABASE_URL`, если секрет короче 32 символов или пуст: это защита, не поломка. Если секрет утёк, замените значение и перезапустите backend: выданные access-токены станут недействительными, refresh-токены продолжат работать (они проверяются по базе).

## Как проверено при включении (25.11.2026)

| Что | Как проверено |
|---|---|
| Аккаунты и история работают | Сквозной сценарий на живом сервере: регистрация, вход, `PUT` занятия, повтор того же `PUT` без дублей, список, сводка, refresh с ротацией, удаление занятия и удаление аккаунта. Все шаги прошли |
| Лимит по IP видит реальный адрес клиента | Проверено на живом сервере. Работает **только после перезапуска Caddy**: при `admin off` Caddy не перечитывает Caddyfile сам (см. ниже) |
| `/health` показывает базу | `GET /api/v1/health` возвращает поле `"database":"ok"` (проверено 25.11.2026 после включения) |
| Режим WAL и внешние ключи SQLite | Включаются кодом при каждом соединении, это проверяет тест `test_sqlite_pragmas`. На самом сервере файл базы я не открывал |

## Как проверить, что всё работает

1. `curl -s https://<домен>/api/v1/health` → `{"status":"ok","mode":"model","version":"0.1.0","database":"ok"}`. Значение `unavailable` значит, что база не открывается (смотреть `docker compose logs --tail=50 backend`).
2. Версия миграций: `docker compose run --rm --no-deps backend alembic current` показывает последнюю (`0002`).
3. Регистрация и удаление тестового пользователя (пароль одноразовый, в журнал не пишется):

```bash
B=https://<домен>/api/v1
curl -s -X POST $B/auth/register -H 'content-type: application/json' -d '{"login":"check_user","password":"<одноразовый пароль 10+ символов>"}'
# из ответа взять access_token, затем:
curl -s -X DELETE $B/me -H "Authorization: Bearer <access_token>" -H 'content-type: application/json' -d '{"password":"<тот же пароль>"}' -w '%{http_code}\n'   # 204
```

4. Лимит по IP: 21 неверный вход с разными логинами с одного адреса: первые 20 дают `401`, 21-й `429`; сразу после этого вход с другого интернета (мобильная сеть) даёт `401`, а не `429`.

```bash
for i in $(seq 1 21); do curl -s -o /dev/null -w '%{http_code} ' -X POST $B/auth/login -H 'content-type: application/json' -d "{\"login\":\"nobody$i\",\"password\":\"wrong-password-$i\"}"; done; echo
```

Если и с другого интернета `429`, backend видит всех клиентов как одного: проверить `trusted_proxies` в Caddyfile и пересоздан ли Caddy.

## Правка Caddyfile и перезапуск Caddy

Caddy запущен с `admin off`, поэтому изменённый `infrastructure/caddy/Caddyfile` он сам не подхватывает: пока контейнер не пересоздан, работает старая настройка. `deploy.sh` делает это сам: если Caddyfile изменился между прошлым и новым коммитом, после запуска сервисов он выполняет `docker compose up -d --force-recreate --wait caddy`, проверяет сайт и `/api/v1/health`, а при откате деплоя возвращает и Caddy. Если Caddyfile не менялся, Caddy не трогается. Вручную: `cd /opt/seriq-ai && docker compose up -d --force-recreate caddy`.

## Как отключить

1. В `/opt/seriq-ai/.env` убрать (или очистить) обе переменные `SERIQ_DATABASE_URL` и `SERIQ_AUTH_SECRET`.
2. `docker compose up -d backend`.

Маршруты `/auth`, `/me`, `/sessions`, `/progress` исчезнут, `/health` перестанет показывать `database`, анализ работает как раньше. Файл базы остаётся в томе `seriq-data`, данные не удаляются; при повторном включении они снова доступны.

| Что нужно | Как |
|---|---|
| Откатить код | `deploy.sh` делает это сам, если деплой не прошёл. Миграции только добавляют таблицы, старый код с новой базой работает |
| Откатить миграцию вручную | `docker compose run --rm --no-deps backend alembic downgrade -1`. **Стирает таблицы последней миграции вместе с данными** |
| Стереть всё без возврата | `docker compose stop backend`, `docker volume rm seriq-ai_seriq-data`. Необратимо |

Резервных копий базы нет: решение руководителя. Удалённые пользователем данные (`DELETE /me`, `DELETE /sessions`) стираются из базы сразу, копий, где они остались бы, нет.

## Время входа рядом с анализом

Хэш пароля (argon2id) тяжёлый, и вход может быть медленнее, пока идёт анализ видео. Измеренные значения и подбор параметров: раздел «Speed and resources» в [model-evaluation.md](../model-evaluation.md). Параметры лежат в `backend/app/services/passwords.py`; новые применяются к паролям при следующем входе пользователя (перехэширование).
