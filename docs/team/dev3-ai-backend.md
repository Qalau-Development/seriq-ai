## 2. Мок-API (первый час)

### Структура

```text
backend/
├── app/
│   ├── main.py                    # создание FastAPI, подключение роутов, обработчики ошибок
│   ├── core/
│   │   ├── config.py              # чтение SERIQ_* из окружения
│   │   └── errors.py              # AppError(code, http_status, message)
│   ├── api/routes/
│   │   ├── health.py              # GET /api/v1/health
│   │   └── analysis.py            # POST /api/v1/analysis
│   ├── schemas/
│   │   └── analysis.py            # Pydantic-модели ответа по api.md
│   └── services/
│       ├── upload.py              # приём файла во временный файл, проверки
│       ├── mock_analysis.py       # фиксированные ответы по mock_scenario
│       └── analysis.py            # режим model: вызов seriq_engine
├── tests/
│   └── test_api.py
├── requirements.txt               # fastapi, uvicorn[standard], python-multipart — с точными версиями (==)
└── requirements-dev.txt           # -r requirements.txt + pytest, httpx — его ставит CI
```

### Обязательно

- **`backend/requirements-dev.txt` обязателен**: CI ставит зависимости для тестов именно из него (`pip install -r requirements-dev.txt`, затем `pytest -q` в папке `backend/`). Без него проверка «Бэкенд» красная, и деплой не пойдёт.
- Версии в `requirements.txt` — точные (`==`). Особенно **scikit-learn**: модель, сохранённая через joblib в одной версии, может не загрузиться в другой. Обучай модель в окружении с той же версией, что в `requirements.txt`.

- `FastAPI(docs_url="/api/docs", openapi_url="/api/openapi.json")`, роуты под префиксом `/api/v1`.
- Комментарии по правилу: одна строка над функцией и роутом, например `# POST /api/v1/analysis — принимает видео и возвращает результат анализа`.
- **Единый формат ошибок** `{"status":"error","error":{"code","message"}}` для всего:
  - своё исключение `AppError` и обработчик для него;
  - обработчик `RequestValidationError` → `400 missing_video`;
  - общий обработчик → `500 internal_error`.
- **Приём файла**:
  - читать потоком во временный файл, прерываться при превышении `SERIQ_MAX_UPLOAD_MB` → `413 file_too_large`;
  - пустой файл → `400 empty_file`;
  - расширение без учёта регистра (`.MOV` с iPhone): `.mp4`, `.mov`, `.webm`, иначе `415 unsupported_format`;
  - сигнатура файла: у mp4/mov байты 4–8 = `ftyp`, у webm первые 4 байта `1A 45 DF A3`;
  - `exercise` не `E02` → `400 unsupported_exercise`;
  - **временный файл удаляется в `finally`**.
- **Один анализ за раз**: `threading.Lock`, `acquire(blocking=False)`; занято → `503 busy`. Роут обычный `def` (не `async def`), тогда FastAPI выполняет тяжёлую работу в пуле потоков и не блокирует сервер.
- `GET /api/v1/health` → `{"status":"ok","mode":<SERIQ_MODE>,"version":"0.1.0"}`.
- **Мок детерминированный**, без случайных чисел. `mock_scenario` выбирает один из четырёх готовых ответов. `analysis_id` новый на каждый запрос, `processing_ms` — реальное время обработки.
- Проверку длительности (`video_too_short`, `video_too_long`) и `video_unreadable` в мок-режиме можно пропустить: для этого нужно декодировать видео. В режиме `model` — обязательно.

## 3. AI-ядро (`ai-engine/`)

```text
ai-engine/
├── pyproject.toml                 # пакет seriq_engine; точные версии mediapipe, opencv-contrib-python, numpy, scipy, scikit-learn, joblib
├── tests/                         # тесты движка, их запускает CI
└── seriq_engine/
    ├── video.py                   # чтение кадров с прореживанием до ~10 fps и уменьшением до 960 px
    ├── hand.py                    # MediaPipe Hand Landmarker: 21 точка кисти по кадрам
    ├── angles.py                  # локоть по траектории запястья, угол локтя по кадрам, пропуски, сглаживание
    ├── features.py                # признаки цикла (один код для обучения и для API)
    ├── classifier.py              # загрузка модели, вероятность, confidence, uncertain
    └── pipeline.py                # analyze_video(path) -> dict по api.md
```

Бэкенд и `ml-training` ставят его как пакет: `pip install -e ai-engine`.

### Что выяснили на данных

- **Плечо в кадре не видно**: рука входит с левого края, видны только предплечье и кулак. MediaPipe Pose Landmarker находит позу в 0–60% кадров, точки плеча и локтя ложные. Угол «плечо — локоть — запястье» посчитать нельзя, Pose не используем.
- **Кисть видна всегда**: MediaPipe Hand Landmarker находит её в 89–100% кадров у каждого из 107 train-видео, включая добровольца с тёмной кожей (vol01). Маску кожи по цвету как метод не берём: на vol01 она теряла до 79% кадров.

### Как считается угол

1. Точка запястья (landmark 0) по кадрам, координаты в пикселях кадра (масштаб одинаковый по осям).
2. **Локоть — центр окружности**, по которой движется запястье. Радиус не свободный, а `K_FOREARM × длина кисти` (запястье → основание среднего пальца, landmark 9). `K_FOREARM = 3,56` подобран на train (vol01–05) — это параметр модели, он фиксируется до прогона на vol08, как порог `uncertain`. Начальная точка подгонки — против направления кисти, поэтому сторона руки определяется сама. Свободная окружность ломается, когда рука почти не двигается: центр уходит в середину предплечья.
3. **Угол локтя = 180° − наклон предплечья** (вектор «локоть → запястье») к горизонтали кадра. Если рука направлена влево, ось x зеркалится.
4. Короткие пропуски (до 3 кадров) интерполируются, длинные остаются `null`; затем скользящее среднее по 3 кадрам.

### Правила

- 180° = рука прямая (это же в api.md). Абсолютный угол зависит от наклона камеры (бывает до ~190°), поэтому **признаки — относительные** (амплитуда, возврат от пика и т. п.), а обрезка до 0–180° — только для `angle_series` в ответе API.
- Кисть найдена в слишком малом числе кадров → `ArmNotFound`, бэкенд превращает его в `422 no_pose_detected`. Доля пропусков больше ~30% → предупреждение `arm_not_visible` (порог уточни по данным).
- `angle_series` в ответе — с той частотой, которую реально посчитал (поле `fps`).
- Веса: `SERIQ_HAND_MODEL_PATH`, в образе `/srv/models/hand_landmarker.task` (скачиваются при сборке, версия 1, проверка sha256). Локально для обучения — `data/processed/mp_models/hand_landmarker.task`.
- Обработку кадров кэшируй: `data/processed/poses/<video_id>.npz` (папка в `.gitignore`), `video_id` включает класс и split, потому что имена файлов не уникальны.
- **Проверка качества**: `ml-training/explore.py` считает невязку окружности и рисует локоть и запястье на кадрах худших видео в `data/processed/qc/` — только локально, кадры добровольцев в репозиторий не кладём.

## 4. Обучение (`ml-training/`)

```text
ml-training/
├── extract_poses.py     # 127 видео → data/processed/poses/*.npz + таблица метаданных
├── explore.py           # графики угла: complete против incomplete, по добровольцам
├── train.py             # признаки, кросс-валидация, выбор модели и порога
└── evaluate.py          # один прогон на vol08, метрики, матрица ошибок
```

### Данные

- **Класс — из имени папки** (`Complete` / `Incomplete`), **не** из имени файла: у vol04 они расходятся.
- ID добровольца — первые две цифры имени файла.
- Видео различать по полному пути: имена у vol04 повторяются.
- Train: vol01–05 (107 видео). Test: vol08 (20 видео).

### Признаки (стартовый набор)

Из ряда угла одного видео: угол в начале и в конце, минимум, максимум, амплитуда (max − min), среднее последних 20% кадров, время до максимума в долях длительности, максимальная и средняя скорость изменения угла, доля кадров с найденной рукой, длительность.

**Не используй признаки, завязанные на камеру**: разрешение, ориентацию, абсолютные пиксели. Train снят на телефон вертикально, test — веб-камерой горизонтально.

### Модели, метрики, порог

Методика целиком — в [model-evaluation.md](../model-evaluation.md): базовая модель, кандидаты, LOSO-CV, метрики (balanced accuracy, precision, recall, F1, матрица ошибок, coverage), калибровка, выбор порога `uncertain`. Здесь только практические моменты:

- `sklearn.pipeline.Pipeline` со `StandardScaler`, чтобы масштабирование обучалось внутри каждого фолда.
- LOSO-CV: `LeaveOneGroupOut`, группы — ID добровольца.
- Порог и калибровку подбирать по out-of-fold предсказаниям LOSO-CV.
- **vol08 не трогать до финала.** Один прогон, после того как модель и порог выбраны.

### Сохранение модели

`joblib.dump` в `models/e02_classifier.joblib` словаря: модель, список признаков, порог, `model_version` (например `e02-rf-1`), дата, версия scikit-learn. Описание — в `models/README.md`.

Файл маленький, его **коммитим**, чтобы он попал на сервер с автодеплоем. Для него в `.gitignore` сделано исключение, обычный `git add models/e02_classifier.joblib` работает. Другие файлы моделей в `models/` по-прежнему игнорируются.

## 5. Подключение модели к бэкенду

1. `services/analysis.py`: при `SERIQ_MODE=model` вызывает `seriq_engine.pipeline.analyze_video(path)` (см. [integration.md](integration.md#5-связь-бэкенда-и-ai-ядра-3)).

3. Ответ той же формы, что и мок; меняется только `source` и `model_version`.
4. Проверь на видео vol08 и на своём видео с телефона.
5. Зависимости `ai-engine` описываются в `ai-engine/pyproject.toml`: Dockerfile бэкенда ставит пакет сам, как только этот файл есть. Тесты движка — в `ai-engine/tests/`, их запускает CI.
6. Поставь `SERIQ_MODE=model` в `.env` на сервере и перезапусти бэкенд (или дождись следующего деплоя). Скажи в чат: «модель на сервере».
