## 1. Линия вдоль руки на видео

**Зачем.** Пользователь сразу видит, «как ИИ видит его руку»: линия от локтя к запястью и точки кисти поверх его собственного видео, синхронно с графиком угла. Линия локоть → запястье — именно то, по чему считается угол.

**Как устроено.**

```text
Сервер (точки кисти уже считает) ──► в ответе необязательное поле pose: точки по кадрам
Сайт / приложение ──► проигрывает видео, которое пользователь только что снял (оно уже на устройстве),
                      поверх рисует линию локоть → запястье и «скелет» кисти
```

Сервер видео не рисует и не хранит: это тяжело для VPS и плохо для приватности.

**Поле в ответе `POST /api/v1/analysis`** (необязательное, и в режиме `model`, и в мок-режиме — там синтетическая детерминированная дуга):

```json
"pose": {
  "fps": 10,
  "elbow": [0.21, 0.78],
  "frames": [
    { "t": 0.0, "wrist": [0.23, 0.31], "hand": [[0.23, 0.31], [0.25, 0.29]] },
    null
  ]
}
```

| Поле | Смысл |
|---|---|
| `fps` | Частота точек, совпадает с `angle_series.fps` |
| `elbow` | Найденный локоть — центр дуги запястья. В долях ширины и высоты кадра; может выходить за 0–1, если локоть за краем кадра |
| `frames[]` | По одному элементу на каждую точку `angle_series.values`; `null` — кисть не найдена |
| `frames[].t` | Время в секундах, как на оси графика |
| `frames[].wrist` | Запястье в долях кадра |
| `frames[].hand` | 21 точка кисти MediaPipe в долях кадра |

Координаты — в долях кадра **в том виде, как видео показывается пользователю**: с учётом поворота из метаданных, как у iPhone. Округление до 4 знаков. Размер ответа для 30-секундной записи проверить отдельно; ожидаемо десятки килобайт.

**Задачи.**

| Кто | Что |
|---|---|
| №3 | Поле `pose` в движке, бэкенде и моке; описание в `docs/api.md` как необязательного; обновить `docs/api-examples/`; тесты |
| №1 | На экране результата: `<video>` с файлом пользователя + `<canvas>` поверх; линия локоть → запястье, точки кисти; синхронизация по `currentTime` и `frames[].t`; разрывы там, где `null` |
| №2 | То же в приложении: `video_player` + `CustomPaint`. По желанию, если остаётся время |

**Проверка.** Свои записи (полное, неполное, «вниз и обратно», рука с другой стороны, iPhone с поворотом): линия лежит вдоль предплечья на всём видео, точка локтя на локте.

## 2. Голосовое чтение результата и инструкции

**Зачем.** Пожилому пользователю проще услышать результат, чем читать с экрана.

**Как.** Встроенный в браузер синтез речи (`speechSynthesis`), без сторонних сервисов и без отправки текста куда-либо. Кнопка «Озвучить» на экране результата и на странице инструкции.

**Что можно озвучивать:** только те фразы, которые уже есть на экране: заголовок результата, строку-пояснение («Рука разогнулась до 147° из 180°…»), шаги инструкции, подсказки о съёмке. **Никаких новых советов о движении.**

**Ограничение.** Русский голос есть почти во всех браузерах, казахский — не везде. Если казахского голоса нет, кнопку на казахском не показывать.

## 3. Анализ в реальном времени во время съёмки

**Зачем.** Во время записи видно точки кисти и угол, человек понимает, что рука в кадре.

**Как.** MediaPipe Hand Landmarker работает прямо в браузере. Расчёт угла (центр дуги запястья) нужно переписать на TypeScript и считать по накапливающимся кадрам. Классификация — по-прежнему на сервере после записи.

**Почему не сейчас.** 4–6 часов работы, высокий риск сломать рабочую запись с камеры, две реализации расчёта угла (Python и TypeScript) нужно держать одинаковыми. Только после конкурса.

## 4. Улучшение модели (после конкурса)

**Проблема, найденная на своих записях.** В датасете полное повторение заканчивается рукой на столе, а возврат вверх встречается только у неполных. Поэтому повторение «до стола и обратно вверх» сейчас даёт `uncertain`, хотя рука разогнулась до 180°. Сейчас это решено инструкцией: «опустите до стола, задержите 1–2 секунды и остановите запись».

**Что сделать.**

- Признак по наибольшему углу (полное — около 180°, неполное — около 130–147°), чтобы возврат вверх не мешал.
- Выделение повторений в одной длинной записи (сейчас одна запись = одно повторение).
- **Новые тестовые данные**: доброволец 08 уже использован, новую модель на нём честно проверить нельзя. Нужны новые записи людей, которых не было в обучении.
